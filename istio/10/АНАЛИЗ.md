# 10. Что даёт Istio для разрешения имён

**Имя сервиса обычно разрешает DNS Kubernetes. Istio добавляет знания о маршрутах
и в некоторых конфигурациях умеет участвовать в DNS-обработке.**
Само наличие реестра сервисов (`Service Registry`) не означает замену DNS.

Сначала рассмотрим обычный вызов:

```text
Приложение: какой IP у payment.shop.svc.cluster.local?
    ↓ DNS Kubernetes (обычно CoreDNS)
Приложение получает IP Service и открывает соединение.
    ↓ Envoy
Proxy применяет маршрут и выбирает backend.
```

Клиенту не нужно знать IP каждого Pod. Но это свойство уже обеспечивается базовыми
механизмами Kubernetes; автоматическое добавление sidecar не создаёт новую
корпоративную DNS-зону.

**В чём различие трёх сущностей**

| Сущность | Её задача |
|---|---|
| DNS | Ответить на вопрос «какому адресу соответствует имя?» |
| Service Registry Istio | Описать известные proxy сервисы и их свойства |
| Маршрут Envoy | Выбрать, как обработать уже перехваченный трафик |

Например, добавили ServiceEntry для `partner.example`. Envoy узнал об этом сервисе,
но обычный DNS-резолвер приложения не обязан сразу начать разрешать такое имя.
Нужен существующий DNS-ответ либо специально настроенный механизм DNS capture.
[DNS и маршрутизация Istio](https://istio.io/latest/docs/ops/configuration/traffic-management/dns/).

**Где Istio может оказаться полезен**

В определённых режимах DNS capture/proxy перехватывает DNS-обращения workload
и помогает обслуживать специальные mesh-имена. Это отдельная функция с условиями
поддержки, а не обязательная предпосылка для каждого HTTP-маршрута. Для нашей
ветки и стенда её включение нужно проверять явно; текущая инструкция его не делает.

Моя оценка: для обычного имени Kubernetes Service сохраняйте стандартную DNS-схему.
Дополнительный DNS capture имеет смысл вводить под конкретный сценарий и с
отдельным испытанием. Иначе при отказе появится лишний вопрос: ошибся CoreDNS,
DNS-перехват или уже HTTP-маршрут.

**Что остаётся в приложении и у платформы**

Код должен использовать логическое имя зависимости и корректно реагировать
на ошибку разрешения/соединения. Платформа сопровождает DNS, домен кластера,
сети и выбранные mesh-настройки. Наличие имени и IP не означает права доступа:
авторизация и изоляция рассматриваются отдельно.
