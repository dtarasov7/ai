# 4. Аутентификация и авторизация. Разграничение доступа (пользователь)

[Практический разбор: что даёт Istio и что остаётся в сервисе](АНАЛИЗ.md).

**Можно:** Частично. **Рекомендация:** Стоит для JWT и грубых правил.

## Как реализуется возможность

RequestAuthentication проверяет подпись, issuer и audience JWT; AuthorizationPolicy требует authenticated principal и нужные claims. Для browser login, MFA, выдачи и обновления токенов нужны IdP и OIDC proxy/приложение. Настройка auth модуля для Kiali не включает SSO автоматически для всех сервисов.

## Плюсы, минусы и границы ответственности

Плюс: общая проверка токена и ограничение HTTP-методов/путей. Минус: зависимость от ключей IdP, кеширования JWKS и сложности отзыва токенов.

RequestAuthentication в одиночку пропускает запрос без токена. Владение заказом, динамические роли и доступ к данным остаются в сервисе либо внешнем authorizer. Нельзя доверять пользовательским заголовкам с ролью без проверки подписи.

Источник: [документация механизма](https://istio.io/latest/docs/reference/config/security/request_authentication/).
Версию/редакцию Deckhouse и условия стенда проверяют по [общему README](../README.md).

## Испытание и критерий

Локальный тестовый RSA-ключ выпускает JWT на час: reader → 200, другая роль → 403, без JWT → 403, повреждённая подпись → 401. Тест не проверяет Dex, login, MFA и refresh.

`01-prepare.sh` создаёт изолированные тестовые ресурсы; `02-check.sh` проверяет
заявленный сценарий; `03-cleanup.sh` удаляет namespace `pmi-istio-4` после проверки
метки владельца. Все три файла запускаются независимо через Bash, из любого каталога.
Порядок: prepare → check → сохранение результатов → cleanup. После неудачи сначала
сохраните диагностику, затем выполните cleanup. См. общие предпосылки и коды выхода.

```bash
bash 01-prepare.sh
bash 02-check.sh
bash 03-cleanup.sh
```

Для протокола сохраните версию DKP/Istio, kube-context, образы с digest, вывод команд,
HTTP-результаты и `kubectl -n pmi-istio-4 get pods,svc -o wide`.
Сценарий создан для испытания; фактическое прохождение на Deckhouse пока не подтверждено.
