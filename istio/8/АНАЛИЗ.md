# 8. Что даёт Istio для группировки сервисов

**Istio умеет выделять группы экземпляров одного сервиса и направлять к ним
разный трафик.** В исходной формулировке «группировка сервисов» это полезный,
но довольно узкий смысл: например, разделение на версии v1 и v2.

Представим две версии «Оплаты», опубликованные под одним именем:

```text
Service «Оплата»
  ├─ subset v1 → Pod с label version=v1
  └─ subset v2 → Pod с label version=v2
```

Service объединяет Pod, DestinationRule называет subsets и связывает их с labels,
VirtualService выбирает нужный subset для запроса. Сам subset не запускает Pod.
[Subsets в DestinationRule](https://istio.io/latest/docs/reference/config/networking/destination-rule/).

Польза для клиента: он продолжает использовать имя «Оплаты». Сведения о том,
какие Pod составляют старую и новую версии, находятся в правилах платформы.
Группа B, например, попадёт в v2, остальные — в v1.

**Почему одного слова «группа» недостаточно**

| Что хотят объединить | Подходящий механизм |
|---|---|
| Реплики одной версии | Labels и subset |
| Реплики одного логического сервиса | Kubernetes Service |
| Приложения одной команды | Labels, namespace и организационные правила |
| Сервисы одной бизнес-системы | Каталог/описание архитектуры и владельцев |
| Разрешённый круг сетевого доступа | Политики авторизации и сетевой изоляции |

Последние строки не возникают автоматически от создания VirtualService.
Например, включение «Оплаты» и «Отчётов» в одну организационную группу
не означает, что у них один API или что любой трафик между ними разрешён.

**Что можно вынести из кода**

Можно убрать из клиентов собственный выбор конкретного набора реплик версии,
если его действительно переносит настроенный маршрут Istio. Но сам признак
группы пользователя, если он нужен, кто-то должен определить и передать.
Бизнес-понятия «платёжные сервисы» или «сервисы арендатора» остаются в модели системы.

Платформа сопровождает согласованность labels, selectors и subsets. Ошибка
в одной метке может сделать группу пустой и привести к отказам, хотя Deployment
будет выглядеть работающим. Это новая эксплуатационная обязанность вместо
собственного ветвления адресов у клиентов.

Моя оценка: использовать subsets стоит для маршрутизации между реальными версиями.
Строить на них универсальный каталог систем или границы безопасности не следует;
для организационной группировки labels и namespace часто достаточны.
