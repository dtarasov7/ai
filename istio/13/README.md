# 13. Реестр внешних сервисов (исходящий трафик)

[Практический разбор: что даёт Istio и что остаётся в сервисе](АНАЛИЗ.md).

**Можно:** Да. **Рекомендация:** Стоит; gateway нужен не всегда.

## Что означает правый столбец

На скриншоте: `Egress gateway`.

Реестр описывает ServiceEntry. Egress gateway — необязательная центральная точка выхода для маршрута, контроля и TLS origination; один gateway не регистрирует внешние API. VirtualService/DestinationRule связывают маршрут и политики.

## Плюсы, минусы и границы ответственности

Плюс: известные внешние зависимости и единые сетевые настройки. Минус: поддержка адресов/портов, DNS, сертификатов; gateway может стать узким местом.

REGISTRY_ONLY защищает от случайных неизвестных направлений внутри proxy, но не является firewall. Принудительный выход через gateway требует CNI/сетевых правил. При сквозном HTTPS нельзя читать HTTP-заголовки без termination.

Источник: [документация механизма](https://istio.io/latest/docs/tasks/traffic-management/egress/egress-control/).
Версию/редакцию Deckhouse и условия стенда проверяют по [общему README](../README.md).

## Испытание и критерий

Изолированный Sidecar REGISTRY_ONLY, ServiceEntry с адресом из benchmark-сети 198.18.0.13 и endpoint тестового Pod без sidecar. Проверяем успех с записью и отказ после удаления, затем восстановление. Это управляемая модель внешнего относительно mesh сервиса, не проверка Internet/egress gateway.

`01-prepare.sh` создаёт изолированные тестовые ресурсы; `02-check.sh` проверяет
заявленный сценарий; `03-cleanup.sh` удаляет namespace `pmi-istio-13` после проверки
метки владельца. Все три файла запускаются независимо через Bash, из любого каталога.
Порядок: prepare → check → сохранение результатов → cleanup. После неудачи сначала
сохраните диагностику, затем выполните cleanup. См. общие предпосылки и коды выхода.

```bash
bash 01-prepare.sh
bash 02-check.sh
bash 03-cleanup.sh
```

Для протокола сохраните версию DKP/Istio, kube-context, образы с digest, вывод команд,
HTTP-результаты и `kubectl -n pmi-istio-13 get pods,svc -o wide`.
Сценарий создан для испытания; фактическое прохождение на Deckhouse пока не подтверждено.
