# 11. Что даёт Istio для изоляции сетей

**Istio добавляет ограничения обращений к приложению по identity и признакам
запроса. Полную сетевую изоляцию нужно строить вместе с механизмами CNI.**
Это два уровня защиты, которые отвечают на разные вопросы.

Пример для «Оплаты»:

```text
CNI/NetworkPolicy: каким Pod вообще разрешено установить соединение?
        ↓
Istio: какой удостоверенный сервис пришёл, какой HTTP-метод и путь он вызывает?
        ↓
Приложение: имеет ли пользователь право оплатить именно этот заказ?
```

В mesh можно разрешить identity «Заказов» только нужные HTTP-операции и потребовать
mTLS. Для этого используются AuthorizationPolicy и PeerAuthentication.
VirtualService управляет маршрутом, а ограничение видимости через exportTo
не заменяет проверку доступа.
[Рекомендации Istio по границам безопасности](https://istio.io/latest/docs/ops/best-practices/security/).

**Практическая добавленная ценность**

Обычная сетевая достижимость ещё не отвечает на вопрос «может ли этот клиент
сделать POST на `/refund`». Proxy с видимым HTTP может применить такое ограничение
до приложения. Политику можно задать одинаково для сервисов на разных языках.

| Требование | Где его проверять |
|---|---|
| Удостоверить вызывающий сервис | mTLS и identity в Istio |
| Ограничить методы и пути | AuthorizationPolicy |
| Ограничить сетевые соединения вне mesh | CNI/NetworkPolicy и сетевые правила |
| Ограничить операции над конкретным заказом | Прикладная авторизация |

Это помогает избежать копирования базового сетевого контроля во все HTTP-серверы.
При этом правила уровня identity требуют разных ServiceAccount для разных
участников: общая учётная запись стирает различие между приложениями.

**Почему нельзя обещать полную изоляцию средствами одного Istio**

Нужно учитывать трафик без sidecar, исключённые из перехвата порты, hostNetwork,
UDP и попытки обхода proxy. Необходимы ограничения прав на Pod и политики,
а также проверка реального применения сетевых правил. Запрет маршрута или
режим REGISTRY_ONLY не равны firewall.

У приложения остаётся бизнес-проверка данных запроса. Даже допустимый
межсервисный вызов может содержать недопустимую операцию над чужими данными.
Платформенная команда сопровождает согласованность CNI- и mesh-политик:
две плоскости контроля дают больше возможностей, но усложняют диагностику отказов.

Моя оценка: использовать Istio как дополнительный уровень правил по identity/L7
разумно, если mesh уже выбран. Заменять им обязательную CNI-изоляцию не следует.
