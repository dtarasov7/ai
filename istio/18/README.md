# 18. Health checks

[Практический разбор: что даёт Istio и что остаётся в сервисе](АНАЛИЗ.md).

**Можно:** Частично. **Рекомендация:** Стоит использовать Kubernetes probes.

## Что означает правый столбец

На скриншоте: `Envoy proxy health checks`.

Kubelet выполняет readiness/liveness/startup probes приложения. Readiness влияет на endpoints, которыми пользуется Envoy; Istio может переписывать HTTP-пробы для работы с sidecar/mTLS. Готовность proxy и здоровье приложения — разные проверки.

## Плюсы, минусы и границы ответственности

Плюс: автоматическое исключение неготовых Pod и согласование с mTLS. Минус: неверная probe вызывает ложные отказы или пропускает неисправность.

В стандартном DestinationRule нет универсальной настройки активных HTTP-проверок приложения. OutlierDetection пассивный. Deckhouse не рекомендует пользовательский EnvoyFilter; через него не следует реализовывать собственную систему probes. Семантику /ready обязан задать сервис.

Источник: [документация механизма](https://istio.io/latest/docs/ops/configuration/mesh/app-health-check/).
Версию/редакцию Deckhouse и условия стенда проверяют по [общему README](../README.md).

## Испытание и критерий

Создаём файл, переводящий /ready у v2 в 503; kubelet снимает Ready, EndpointSlice помечает endpoint неготовым, трафик остаётся на v1. Удаляем файл, ждём восстановления и снова видим v2. liveness/restart и бизнес-диагностика не проверяются.

`01-prepare.sh` создаёт изолированные тестовые ресурсы; `02-check.sh` проверяет
заявленный сценарий; `03-cleanup.sh` удаляет namespace `pmi-istio-18` после проверки
метки владельца. Все три файла запускаются независимо через Bash, из любого каталога.
Порядок: prepare → check → сохранение результатов → cleanup. После неудачи сначала
сохраните диагностику, затем выполните cleanup. См. общие предпосылки и коды выхода.

```bash
bash 01-prepare.sh
bash 02-check.sh
bash 03-cleanup.sh
```

Для протокола сохраните версию DKP/Istio, kube-context, образы с digest, вывод команд,
HTTP-результаты и `kubectl -n pmi-istio-18 get pods,svc -o wide`.
Сценарий создан для испытания; фактическое прохождение на Deckhouse пока не подтверждено.
