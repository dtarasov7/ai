# Сводная оценка возможностей Istio

Таблица содержит оценку 23 возможностей Istio. «Частично» означает, что перенос
всей функции из приложения в Istio невозможен. Столбец «Анализ» поясняет, какую работу можно
вынести из приложений и какие дополнительные возможности получит команда.
Подробности и источники доступны через README соответствующего пункта.
Рекомендации не означают, что испытания уже пройдены.

| № | Пункт | Можно средствами Istio | Стоит ли делать | Анализ |
| --- | --- | --- | --- | --- |
| [1](1/README.md) | Маршрутизация трафика ППО внутри (east-west) и вне кластера | Да | Стоит | Не нужно в каждом приложении писать правила выбора версии вызываемого сервиса. Можно централизованно направлять разные запросы в разные версии и менять эти правила без перевыпуска приложений. |
| [2](2/README.md) | Конфигурирование обнаружения сервисов и управления трафиком (pilot) | Да | Стоит | Не нужно разрабатывать собственную систему доставки сетевых настроек всем сервисам. Изменения правил взаимодействия и адресов работающих экземпляров распространяются централизованно. |
| [3](3/README.md) | Аутентификация и авторизация. Разграничение доступа (система) | Да, для межсервисного доступа | Стоит | Можно вынести из сервисов защиту соединений и общие проверки того, каким сервисам разрешено обращаться друг к другу. Проверка прав на бизнес-сущности и допустимости бизнес-операций остаётся в приложении. |
| [4](4/README.md) | Аутентификация и авторизация. Разграничение доступа (пользователь) | Частично | Стоит для JWT и грубых правил | Можно вынести из приложений проверку подлинности данных о пользователе и общие ограничения доступа по его роли. Организация входа в систему требует отдельных средств; проверка прав на бизнес-сущности и допустимости бизнес-операций остаётся в приложении. |
| [5](5/README.md) | Наблюдаемость сервисов (сбор логов, трейсов, метрик) | Частично | Стоит как дополнение | Получаем общую картину взаимодействия сервисов: число вызовов, ошибки и задержки. Не нужно отдельно реализовывать сбор одинаковых показателей взаимодействия в каждом сервисе; сведения о бизнес-событиях и внутренних действиях добавляет приложение. |
| [6](6/README.md) | Обнаружение сервисов | Да | Стоит; Kubernetes часто достаточен | Не нужно хранить в приложениях списки адресов всех экземпляров зависимого сервиса и самостоятельно обновлять их при запуске или остановке экземпляров. Базовую возможность уже даёт Kubernetes; Istio дополняет её общими правилами взаимодействия. |
| [7](7/README.md) | Хранение конфигурации ОКС (istiod) | Нет как универсальное хранилище; да для mesh-конфигурации | Не стоит для конфигурации приложения | Получаем единое место управления правилами взаимодействия сервисов. Хранение прикладных настроек и управление параметрами бизнес-логики требуют отдельного решения. |
| [8](8/README.md) | Группировка сервисов | Частично | Стоит для версий; не для каталога систем | Можно разделять экземпляры сервиса на группы, например по версиям, и отдельно направлять к ним запросы. Приложениям не нужно самостоятельно хранить состав этих групп и выбирать адреса их участников. |
| [9](9/README.md) | Управление стратегиями развёртывания | Частично | Стоит в связке с CI/CD | Можно управлять переводом запросов на новую версию без изменения вызывающих приложений. Развёртывание самих версий и решение о продолжении или откате обновления остаются частью процесса выпуска. |
| [10](10/README.md) | Разрешение имён | Частично | Kubernetes DNS — основа; Istio по необходимости | Приложение может обращаться к зависимости по постоянному имени, не отслеживая смену её адреса. В Kubernetes это уже доступно без Istio; дополнительная польза Istio возникает при подключении внешних сервисов и специальных настройках разрешения имён. |
| [11](11/README.md) | Изоляция сетей | Частично | Стоит совместно с CNI | Не нужно дублировать в каждом сервисе общие запреты на вызовы от других сервисов. Получаем централизованные ограничения взаимодействия; полную сетевую изоляцию обеспечивают вместе с другими средствами платформы. |
| [12](12/README.md) | Публикация сервисов (входящий трафик) | Да | Стоит при использовании mesh | Получаем единую точку приёма внешних запросов и общие правила их распределения между сервисами. Эту логику не нужно реализовывать в приложениях; публикацией сервисов можно управлять без изменения их кода. |
| [13](13/README.md) | Реестр внешних сервисов (исходящий трафик) | Да | Стоит; gateway нужен не всегда | Получаем общий перечень внешних систем и единые правила обращений к ним. Можно централизованно управлять выходом во внешние системы; формирование прикладных запросов и обработка результатов остаются в приложении. |
| [14](14/README.md) | Circuit breaker | Да, сетевой | Стоит с настройкой под нагрузку | Можно вынести из вызывающих приложений ограничения числа одновременных обращений и размера очереди запросов к зависимому сервису. Получаем защиту от части перегрузок и возможность временно исключать сбоящие экземпляры из распределения запросов; обработку отказа в рамках бизнес-операции определяет приложение. |
| [15](15/README.md) | Canary, blue-green | Да, распределение трафика | Стоит совместно с CI/CD | Можно сначала направить на новую версию небольшую долю запросов, затем увеличить её или быстро вернуть запросы на прежнюю версию. В вызывающих приложениях не нужно писать эту логику; возврат трафика не отменяет уже сделанные изменения данных. |
| [16](16/README.md) | A/B | Да для маршрута; частично для эксперимента | Стоит при доверенном назначении группы | Можно направлять разные группы пользователей в разные версии сервиса для сравнения поведения. Не нужно писать выбор версии в каждом вызывающем приложении; назначение пользователей в группы и оценку результатов эксперимента нужно организовать отдельно. |
| [17](17/README.md) | Sticky sessions | Да, мягкая привязка | Условно; предпочесть внешнее хранение сессий | Можно вынести из приложения правила направления связанных запросов к одному экземпляру сервиса. Такая привязка не гарантируется при отказе или замене экземпляра; сохранение состояния сессии требует отдельного решения. |
| [18](18/README.md) | Health checks | Частично | Стоит использовать Kubernetes probes | Можно автоматически учитывать наблюдаемые ошибки экземпляров при распределении запросов. Проверки готовности и перезапуск уже предоставляет Kubernetes; приложение должно сообщать, когда оно действительно готово обслуживать запросы. |
| [19](19/README.md) | Отображение топологии и информационных потоков | Да для наблюдаемого трафика | Стоит | Получаем наглядную схему фактического взаимодействия сервисов с показателями ошибок и задержек, что упрощает поиск проблем. Не нужно собирать такую схему средствами приложений; она отражает наблюдаемые вызовы и не описывает бизнес-смысл взаимодействия. |
| [20](20/README.md) | Сервисы на обычных ВМ | Да в upstream; поддержка ОС/поставкой требует проверки | Стоит для legacy-сервисов | Можно включить сервисы на обычных ВМ в общие правила защищённого взаимодействия и наблюдения вместе с сервисами Kubernetes. Переносить их в контейнеры ради этого не обязательно; применимость к выбранной ОС и поставке нужно подтвердить. |
| [21](21/README.md) | Fault injection | Да, HTTP delay/abort | Стоит для тестирования | Можно намеренно задерживать обращения к зависимому сервису или возвращать ошибки, чтобы проверить устойчивость вызывающего сервиса. Специальный код имитации этих сбоев в вызываемом приложении не требуется. |
| [22](22/README.md) | Retries | Да, по условиям политики | Стоит выборочно для безопасных операций | Можно вынести из приложения повторные обращения при заданных временных сбоях: вызывающий сервис обычно получает итоговый ответ. Предотвращение нежелательных последствий повторного выполнения бизнес-операций остаётся ответственностью приложения. |
| [23](23/README.md) | Timeout | Да, ограничение ожидания proxy | Стоит вместе с прикладными дедлайнами | Можно централизованно ограничить ожидание ответа зависимости, чтобы отдельный вызов не затягивался бесконечно. Вызывающий сервис получает ошибку и должен обработать её; ограничение ожидания не гарантирует остановку работы или отмену операции у получателя. |
