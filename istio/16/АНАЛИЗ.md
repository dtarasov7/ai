# 16. Что даёт Istio для A/B

**Istio позволяет направлять устойчиво определённую группу запросов в нужную
версию backend.** Это сетевая часть A/B-эксперимента: выбор варианта доставки,
а не сама система проведения экспериментов.

Представим две реализации расчёта предложения. Система экспериментов заранее
назначила пользователю группу A или B:

```text
Пользователь группы A → доверенный признак группы → Envoy → backend v1
Пользователь группы B → доверенный признак группы → Envoy → backend v2
```

VirtualService может сопоставить заголовок или cookie с маршрутом.
При сохранении того же признака пользователь продолжает обращаться к варианту
своей группы. Это отличается от случайного выбора версии по весу на каждом запросе.
[Маршрутизация по признакам запроса](https://istio.io/latest/docs/tasks/traffic-management/request-routing/).

**Что нужно построить помимо маршрута**

| Часть A/B | Кто отвечает |
|---|---|
| Назначить участника группе | Система экспериментов или доверенный код |
| Сохранить группу между обращениями | Сессия, cookie или другой выбранный механизм |
| Доставить запрос нужному backend | Istio при настроенном маршруте |
| Измерить результат и сделать вывод | Прикладная аналитика и методика эксперимента |

Например, Envoy может отправить группу B в v2, но он не знает, улучшилось ли
качество рекомендации или выросла ли конверсия. Сбор целевых бизнес-событий
и статистическую оценку нельзя заменить метрикой HTTP 200.

**Что можно убрать из сервисного кода**

Если варианты представлены отдельными версиями сервиса, не нужно дублировать
в каждом его клиенте условие «для B используй другой адрес». Выбор backend
централизован. При этом назначение группы и передача её признака должны остаться
в согласованной части системы.

Если различие вариантов находится внутри одного обработчика, маршрутизация mesh
сама по себе не заменяет соответствующее ветвление или feature flag.
Нужно сначала определить, действительно ли эксперимент представлен разными
сетевыми назначениями.

**Надёжность и ограничения**

Пользовательский `x-cohort` можно подделать. Для защищённых сценариев признак
назначает или проверяет доверенный компонент, а пограничные заголовки очищаются
по выбранной схеме. Группу эксперимента нельзя считать доказательством прав доступа.

Также нужно согласовать поведение связанных сервисов: один сетевой переход
на v2 не означает, что вся бизнес-операция прошла через один согласованный набор
версий. Это особенно важно для состояния и несовместимых форматов данных.

Моя оценка: Istio полезен для доставки участников в отдельные backend-варианты.
Выбор участников, продуктовые выводы и безопасность требуют самостоятельного проекта.
Сравните с [canary](../15/АНАЛИЗ.md) и [sticky sessions](../17/АНАЛИЗ.md).
