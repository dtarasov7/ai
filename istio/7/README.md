# 7. Хранение конфигурации ОКС (istiod)

[Практический разбор: что даёт Istio и что остаётся в сервисе](АНАЛИЗ.md).

**Можно:** Нет как универсальное хранилище; да для mesh-конфигурации. **Рекомендация:** Не стоит для конфигурации приложения.

## Как реализуется возможность

Если речь о конфигурации mesh, ресурсы Istio сохраняются через Kubernetes API в datastore кластера, а istiod читает и преобразует их.
В обычном Kubernetes это etcd; на одноузловом K3s из нашей инструкции — SQLite. Если речь о настройках приложения, используйте ConfigMap/Secret, GitOps либо специализированное хранилище; istiod для этого не подходит.

## Плюсы, минусы и границы ответственности

Плюс штатных CRD: версионирование деклараций и Kubernetes RBAC. Минус: резервирование datastore/Git и защита секретов требуют отдельного решения.

Кеш istiod/Envoy не заменяет долговечное хранилище, резервные копии или доставку бизнес-настроек. Изменения конфигурации mesh в Git и реальные ресурсы могут расходиться.

Источник: [документация механизма](https://istio.io/latest/docs/ops/deployment/architecture/).
Версию/редакцию Deckhouse и условия стенда проверяют по [общему README](../README.md).

## Испытание и критерий

Для допустимого узкого смысла сохраняем VirtualService, пересоздаём только тестовый клиент и проверяем применение того же маршрута новым proxy. Это не испытание отказа etcd, восстановления или доступности istiod.

`01-prepare.sh` создаёт изолированные тестовые ресурсы; `02-check.sh` проверяет
заявленный сценарий; `03-cleanup.sh` удаляет namespace `pmi-istio-7` после проверки
метки владельца. Все три файла запускаются независимо через Bash, из любого каталога.
Порядок: prepare → check → сохранение результатов → cleanup. После неудачи сначала
сохраните диагностику, затем выполните cleanup. См. общие предпосылки и коды выхода.

```bash
bash 01-prepare.sh
bash 02-check.sh
bash 03-cleanup.sh
```

Для протокола сохраните версию DKP/Istio, kube-context, образы с digest, вывод команд,
HTTP-результаты и `kubectl -n pmi-istio-7 get pods,svc -o wide`.
Сценарий создан для испытания; фактическое прохождение на Deckhouse пока не подтверждено.
