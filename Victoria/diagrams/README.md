# Схемы VictoriaMetrics

Восемь самостоятельных схем в стиле исходного `1.png`. PNG предназначены для вставки в документы; SVG — для редактирования и масштабирования.

| Файл | Размер PNG |
| --- | --- |
| 01-cluster-internal-traffic | 1800 × 1400 |
| 02-grafana-read-flow | 1800 × 1400 |
| 03-prometheus-write-flow | 1800 × 1400 |
| 04-admin-gui-access | 1800 × 1660 |
| 05-vmalert-alertmanager-ha | 1800 × 1680 |
| 06-vmbackup-flow | 1800 × 1600 |
| 07-vmrestore-flow | 1800 × 1600 |
| 08-vmagent-flow | 1800 × 1900 |

Описание, исправления и первичные источники находятся в `../all-schemes.md`. Главное изменение схемы №5: локальный `vmauth` вместо непроверенного доступа к собственному LVS-DR VIP; HA реализуется тремя одинаково настроенными `vmalert`. Схемы №2–4 сохраняют внешний вход через VIP.

Линии выбора HTTP-backend означают возможные маршруты, а не отправку одного запроса всем backend. Для Alertmanager, наоборот, каждый алерт направляется всем трём получателям. Пересечения линий без обозначенного узла не являются сетевыми компонентами.

Повторная генерация из корня проекта:

```sh
python diagrams/render.py
python diagrams/render_backup.py
python diagrams/render_vmagent.py
```

Нужны Python 3, системные библиотеки librsvg-2, Cairo, GObject и шрифт Open Sans. Установка Python-пакетов для генерации не требуется.

Проверено: генерация PNG; открытие PNG; разбор SVG; по три экземпляра каждого участвующего компонента; направления стрелок и визуальная читаемость; UTF-8 и LF в текстовых файлах. Работоспособность развёрнутой сети не тестировалась.

Подробный разбор отказов для каждой схемы: [HA-scenarios.md](HA-scenarios.md).

Редактируемая схема №2 с 23 привязанными соединителями, одна страница: [VSDX](02-grafana-read-flow.vsdx), [особенности редактирования](02-grafana-read-flow-visio.md), [предпросмотр независимым рендерером](02-grafana-read-flow-visio-preview.png).

Все восемь схем доступны в VSDX: одна страница, редактируемые карточки и привязанные соединители. [Инструкция по редактированию](visio-editing.md). Предпросмотры: файлы *-visio-preview.png.

Схемы №6 и №7: резервное копирование и восстановление, пояснения — в разделах 11–12 файла `../all-schemes.md`. Цветные линии обозначают управление и поток данных, серый пунктир — локальные этапы; это указано в легендах.

Схема №8: [PNG](08-vmagent-flow.png), [SVG](08-vmagent-flow.svg), [VSDX](08-vmagent-flow.vsdx). Фиолетовые стрелки обозначают scrape-запросы; карточки endpoints объединяют несколько целей каждого узла. Пояснения — в разделах 13–14 файла `../all-schemes.md`.

Схема №4: адресная диагностика `/diag/<компонент>/<имя_узла>/`, пользователь `diagnostics`, пять backend-компонентов. Административный вход использует HTTPS; соединения к backend — HTTP с внутренней Basic Auth.

## Схема №9 — один и два тенанта

[PNG](09-single-vs-two-tenants.png) · [SVG](09-single-vs-two-tenants.svg) · [VSDX](09-single-vs-two-tenants.vsdx).
Два варианта рядом: cluster-компоненты на одном сервере, RF=1; отдельные vmagent/vmalert на тенант и общие компоненты хранения и доступа. Пояснения — раздел 15 [архитектуры](../all-schemes.md). Генерация: `python diagrams/render_tenants.py`, затем `python diagrams/visio-source/build_vsdx.py 9`. Проверка соединителей: `python diagrams/visio-source/verify_connectors.py 9` из корня проекта.
