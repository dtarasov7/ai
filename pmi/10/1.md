## 1. Что демонстрируется

В версии Deckhouse 1.73 реализована проверка запросов `CONNECT` к `pods/exec` через Gatekeeper. Это позволяет отклонять `kubectl exec` до выполнения команды внутри контейнера.&#x20;

## 2. Назначение скриптов

| Скрипт          | Функция                                                                                                                       |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `01-prepare.sh` | Создаёт Namespace и Pod, проверяет успешный `exec`, затем устанавливает Gatekeeper ConstraintTemplate и Constraint с запретом |
| `02-check.sh`   | Проверяет, что `kubectl exec` запрещён именно Gatekeeper, а Pod продолжает работать                                           |
| `03-cleanup.sh` | Удаляет тестовый Namespace, Pod и созданные ресурсы Gatekeeper                                                                |

Тестовая политика действует только в Namespace `gatekeeper-exec-demo`. Системные Namespace не затрагиваются.

## 3. Запуск

Распакуйте архив на машине с доступом к кластеру и выполните:

```
chmod +x *.sh

# Подготовка
./01-prepare.sh

# Демонстрация запрета
./02-check.sh

# Очистка после испытаний
./03-cleanup.sh
```

По умолчанию используется `kubectl`. Для Deckhouse CLI можно задать:

```
export KUBECTL=d8
```

Если используете другой реестр образов, можно переопределить `DEMO_IMAGE`.

## 4. Ожидаемый результат проверки

До включения политики:

```
PASS: BASELINE_EXEC_OK
```

После включения политики попытка:

```
kubectl -n gatekeeper-exec-demo exec exec-test -- id
```

должна приводить к отказу с маркером:

```
DEMO_GATEKEEPER_EXEC_DENIED:
kubectl exec is prohibited by Gatekeeper
```

Итог проверки:

```
[1/3] Existing Pod is running...
[2/3] kubectl exec is expected to be denied by Gatekeeper...
PASS: Gatekeeper rejected the API CONNECT request
[3/3] Pod is still Running / application continues...
PASS: Pod Running, but external kubectl exec blocked.
OVERALL RESULT: PASS
```

Это ожидаемый вывод, а не результат запуска на вашем кластере. Проверку синтаксиса Bash скрипты прошли; реальное испытание требует доступа к Deckhouse.

## 5. Критерий успешности испытания

Требование: платформа должна обеспечивать возможность запрета внешнего выполнения команд в контейнере через `kubectl exec` средствами политик безопасности Gatekeeper.

Критерий подтверждения: до применения политики команда выполняется, после применения Gatekeeper возвращает явный отказ, а тестовый Pod остаётся в состоянии `Running`.

Это подтверждает управление доступом на уровне Kubernetes API. Политика не запрещает выполнение команд самим процессом внутри контейнера и не прерывает уже установленные exec-сессии.

Реализация основана на механизме Gatekeeper `ConstraintTemplate`/`Constraint` и поддержке `CONNECT` в Deckhouse.&#x20;
