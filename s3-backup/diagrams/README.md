# Схемы резервного копирования и восстановления MinIO

- `01-backup.vsdx` — регулярная синхронизация S3 в файловое зеркало и последующее резервное копирование средствами СРК.
- `02-restore.vsdx` — восстановление всех данных, одного бакета или части бакета через отдельный каталог.
- Одноимённые `.svg` — копии схем для просмотра в браузере.
- `*-visio-preview.png` — отрисовки исправленных VSDX через libvisio.
- `visio-document.xml` — настройки документа и базовый стиль из рабочего примера пользователя; лицензия шаблона сохранена в `TEMPLATE-LICENSE.txt`.
- `generate.py` — воспроизводимая генерация файлов: `python diagrams/generate.py` (Python 3, Pillow и шрифт `/usr/share/fonts/liberation/LiberationSans-Regular.ttf`).

Каждый VSDX содержит одну страницу. Блоки, стрелки и подписи — собственные редактируемые фигуры Visio, а не вставленная картинка. Пути и имена бакетов условные.

## Принятые условия

1. Для каждого бакета используется отдельный каталог зеркала. `rclone sync` переносит добавления и изменения, а также удаляет из зеркала отсутствующие в источнике файлы. Историю хранит СРК.
2. СРК читает зеркало после успешного завершения синхронизации всех выбранных бакетов. Следующая синхронизация ждёт завершения чтения либо СРК читает неизменяемый снимок файловой системы.
3. Синхронизация изменяемого S3 сама по себе не обеспечивает согласованный срез на один момент времени. Если это требуется, необходимо отдельно согласовать остановку записи или механизм согласованного копирования.
4. При восстановлении сохраняется соответствие «каталог бакета → бакет» и относительных путей ключам объектов. Для части бакета выбираются нужные префиксы или объекты.
5. Для обычного восстановления показан `rclone copy`: он не удаляет прочие объекты целевого бакета. Полное восстановление поверх непустого бакета поэтому не является точным откатом его состава. Для точного состава предпочтителен пустой целевой бакет; его создание и настройки планируются отдельно.
6. Схемы описывают содержимое текущих объектов. Версии S3, настройки бакетов, политики, теги, Object Lock и прочие метаданные нельзя считать сохранёнными автоматически. Их резервное копирование и обратимость отображения S3-ключей в файловые пути требуют отдельной проверки.
7. Ёмкость сервера должна учитывать все зеркалируемые бакеты, каталог восстановления и, при использовании, снимки ФС. Изменения менее 1% не исключают обхода списка объектов и не определяют автоматически объём чтения СРК.

## Проверка

Исправлен MIME-тип основной части: `application/vnd.ms-visio.drawing.main+xml`. Структура документа, настройки страницы, стили и шрифты приведены к рабочему примеру из каталога `0`. Подписи разбиты на отдельные редактируемые строки внутри групп, чтобы исключить наложение при отрисовке.

Проверены целостность ZIP, разбор всех XML, типы содержимого, внутренние связи, уникальность идентификаторов фигур, ссылки на шрифты и стили, сохранность подписей. Обе схемы прочитаны и отрисованы libvisio 0.1.7 как одностраничные документы; PNG проверены визуально. Microsoft Visio в среде отсутствует. Результат проверки записан в `VALIDATION.txt`.
