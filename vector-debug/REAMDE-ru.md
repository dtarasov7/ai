# VRL Debugger 1.2.0

[English](README.md) | Русский | [История изменений](CHANGELOG-ru.md)

Консольный отладчик VRL-программ для Vector. Помогает понять, как программа
преобразует данные, найти причину ошибки и проверить исправление.

## Возможности

- **Пошаговое выполнение VRL-программ** с просмотром результата каждого шага.
- **Возврат к предыдущим шагам** для сравнения значений и повторного разбора работы программы.
- **Разбор условий и циклов:** вход в выбранную ветку условия, просмотр отдельных итераций, завершение текущей итерации или всего цикла.
- **Остановка перед нужной командой** — по номеру строки или при выполнении условия, например только на третьей итерации цикла.
- **Просмотр данных и переменных:** всех сразу или только выбранных значений с автоматическим обновлением после каждого шага.
- **Просмотр изменений:** какие поля и переменные появились, изменились или исчезли после выполнения команды.
- **Изменение значений во время отладки** для проверки другого поведения программы без редактирования её текста, с возможностью отменить правки.
- **Просмотр исходного кода** с выделением команды, которая будет выполнена следующей.
- **Разбор ошибок:** просмотр сообщения об ошибке и значений, полученных перед её возникновением.
- **Отладка на собственных данных** из JSON или выбранной записи JSONL.
- **Настройка вывода:** скрытие больших разделов с данными, выбор цветов и повторный вызов команд из истории.

Версия **1.2.0**, выпущена **2026-10-08**. Проверить версию:

```bash
python3 vrl_debug.py --version
```

## Требования и запуск

Linux, Python **3.8+**, Vector с командой `vrl`. Зависимости — только Python Standard Library.
Установка Python-пакетов не нужна.

`vrl_debug.py` — автономный **single-file** вариант. Для переноса на другую машину
достаточно скопировать этот файл; каталог `vrl_debugger/` не нужен. VRL-программу,
входной JSON и установленный бинарник Vector указывайте при запуске как обычно.

```bash
python3 vrl_debug.py --program example-simple.vrl --input event-simple.json
```

Если Vector отсутствует в PATH, укажите путь:

```bash
python3 vrl_debug.py --vector /usr/bin/vector --program example-simple.vrl --input event-simple.json
```

В рабочем каталоге этой реализации для интеграционных проверок загружен Vector 0.58.0
из официального архива `packages.timber.io`. С ним пример запускается так:

```bash
python3 vrl_debug.py \
  --vector .tools/vector-x86_64-unknown-linux-gnu/bin/vector \
  --program example-simple.vrl --input event-simple.json
```

`.tools/` — локальные инструменты, не часть исходного кода и не обязательная зависимость проекта.
При старте отладчик вызывает `vector --version`, проверяет `vector vrl --help`,
выводит версию и проверяет реальный обмен данными тестовым event.
Отсутствующий бинарник или несовместимый CLI дают понятную ошибку.

## Примеры

| Программа | Входной JSON | Назначение |
| --- | --- | --- |
| [example-simple.vrl](example-simple.vrl) | [event-simple.json](event-simple.json) | Первые шаги: разбор JSON, вход в `if`, удаление поля |
| [example.vrl](example.vrl) | [event.json](event.json) | Расширенные проверки: циклы, locals, вычисления, обработка ошибок |

Команды запуска выше используют простой пример. Для отладки циклов см. [Проверки на расширенном примере](#проверки-на-расширенном-примере).

### Простой пример

`example-simple.vrl`:

```vrl
parsed = parse_json!(.message)
.level = parsed.level

if exists(parsed.user) {
    .user = parsed.user
}

del(.message)
.processed = true
```

Соответствующий `event-simple.json`:

```json
{
  "message": "{\"level\":\"INFO\",\"user\":\"alice\"}",
  "host": "srv01"
}
```

После выполнения всей программы event будет таким:

```json
{"host": "srv01", "level": "INFO", "user": "alice", "processed": true}
```

После двух команд `next` появится `.level = "INFO"`, в locals будет `parsed`,
а diff покажет добавление `.level`. Команда `next` выполняет весь следующий `if`,
а `i` / `step into` позволяет войти в выбранную ветку.

```text
next
next
event
diff
step into
next
previous
goto 5
break 5
restart
continue
breakpoints
quit
```

## Команды

| Команда | Действие |
| --- | --- |
| `n`, `next` | Выполнить следующее выражение в текущей области целиком |
| `i`, `into`, `step into` | Войти в ветку `if/else` или пройти итерации `for_each` |
| `p`, `prev`, `previous` | Перейти на предыдущий шаг |
| `c`, `continue` | Выполнять до breakpoint, ошибки или конца |
| `fi`, `finish iteration` | Завершить текущую итерацию и остановиться перед следующей |
| `fl`, `finish loop` | Завершить оставшиеся итерации и остановиться сразу после цикла |
| `g N`, `goto N` | Перейти к **номеру top-level expression**; 0 — исходное состояние |
| `b LINE [if EXPR]`, `break LINE [if EXPR]` | Остановиться перед командой, при необходимости по условию VRL |
| `until LINE` | Выполнять до строки без добавления постоянного breakpoint |
| `bl`, `breakpoints` | Показать breakpoints |
| `bd LINE`, `delete-breakpoint LINE` | Удалить breakpoint, заданный для LINE |
| `print PATH` | Показать одно поле event или доступную локальную переменную |
| `watch [PATH]` | Добавить путь в наблюдения или показать все наблюдения |
| `unwatch PATH` | Удалить наблюдение |
| `set PATH = JSON` | Изменить значение в текущей позиции выполнения |
| `edits`, `edits clear` | Показать правки или удалить их все с повторным выполнением |
| `undo` | Удалить последнюю правку и повторно дойти до текущей позиции |
| `diff locals` | Показать изменения locals текущей области |
| `e`, `event` | Показать event |
| `l`, `locals` | Показать захваченные локальные переменные |
| `show event on`, `show event off` | Включить или выключить автоматический вывод EVENT |
| `show locals on`, `show locals off` | Включить или выключить автоматический вывод LOCALS |
| `d`, `diff` | Показать изменения относительно предыдущего expression |
| `src`, `source` | Показать исходник вокруг текущего expression |
| `src all`, `source all` | Показать всю программу с исходными номерами строк |
| `r`, `restart` | Вернуться к шагу 0; кеш и breakpoints сохраняются |
| `h`, `help` | Справка |
| `q`, `quit` | Выход; EOF также завершает сессию |

Breakpoints задаются по исходным строкам и останавливают **до выполнения**.
`continue` автоматически входит в поддерживаемые ветки `if/else` и тела `for_each`,
чтобы дойти до внутренней команды. Breakpoint тела цикла проверяется в каждой
итерации. Вложенные блоки внутри тела цикла по-прежнему выполняются целиком:
строка внутри такого блока привязывается ко всему вложенному блоку. Фактическую
точку показывает выведенный диапазон строк. Пустые строки и комментарии привязываются
к следующей поддерживаемой команде, закрывающая скобка — к содержащему блоку.
Строки после последнего expression не принимаются.

Для расширенного примера условная остановка задаётся как `b 44 if key == "env"`.
Условие вычисляет Vector на копии текущего JSON-event и захваченных locals;
результат должен быть boolean. Недоступная переменная, ошибка компиляции или другой
тип результата дают ошибку команды без выполнения остановленного выражения.
Типы соответствуют JSON-снимку, а не исходным timestamp/regex/bytes. Используйте
условия без побочных эффектов; состояние отладчика условие не изменяет.

Повторный `continue` один раз проходит текущую остановку. Ручная навигация и
`restart` снова активируют её. `next`, `step into`, `goto`, `fi` и `fl` игнорируют
breakpoints. `until LINE` учитывает существующие breakpoints и ошибки, не создавая
постоянную точку остановки. Если уже стоим на нужной команде, позиция сохраняется;
иначе выполнение идёт вперёд. Недостижимая строка, например в невыбранной ветке,
приводит к выполнению до конца или другой остановки. Удаление выполняется по строке,
с которой был задан breakpoint (`bd LINE`); номер expression в выводе лишь указывает
на содержащее top-level выражение.

Стрелка `>` отмечает весь диапазон expression, который будет выполнен следующим
шагом. На шаге 0 она указывает на первый expression; после последнего шага стрелки
нет и выводится `(end of program)`. Event, locals и diff показывают уже полученное
состояние. При ошибке символ `!` отмечает неуспешный expression, а event и locals
остаются от последнего успешного шага. Ошибка не закрывает REPL: доступны `previous`, `source`,
`event`, `restart`, `quit`. `goto` останавливается на первом ошибочном префиксе.

Команды `show event off` и `show locals off` скрывают соответствующие секции
при последующем выводе состояния. Вернуть их можно через `show event on` и
`show locals on`. Эти команды не перемещают выполнение. Команды `event` / `e`
и `locals` / `l` всегда показывают данные по запросу, даже при отключённом
автоматическом выводе. Настройки сохраняются при `restart` в текущей сессии;
`show event on` также отменяет начальное скрытие через `--no-event`.

В интерактивном терминале стрелки **↑** и **↓** выбирают команды, введённые в текущей
сессии. Редактирование строки и историю обеспечивает стандартный модуль `readline`;
история хранится в памяти и не записывается в файл. Цветное приглашение учитывает
невидимые ANSI-коды, чтобы курсор перемещался правильно. При перенаправлении ввода
или вывода используется обычный построчный ввод. Если в Python отсутствует
`readline`, отладчик объясняет, почему история команд недоступна.

Команда `source all` выводит каждую строку программы и выделяет текущую позицию
теми же маркерами, что и `source`. Она не перемещает выполнение и не запускает
Vector. Пустые строки и программы, состоящие только из комментариев, тоже выводятся.

### Просмотр и изменение значений

`print` и `watch` читают захваченные значения без выполнения VRL. Поддерживаются
корень event (`.`), имена locals, поля через точку, неотрицательные индексы массива
и строковые JSON-ключи: `.items[0].price`, `parsed.level`, `.labels["a.b"]`.
Произвольные VRL-выражения эти команды не вычисляют. Отсутствующие поля и locals
помечаются как недоступные; JSON `null` отличается от отсутствующего значения.
Наблюдение можно добавить до появления переменной. WATCH остаётся видимым при
отключённом автоматическом выводе EVENT и LOCALS.

```text
show event off
show locals off
watch normalized
watch .normalized_labels
b 44 if key == "env"
c
print normalized
set normalized = "CUSTOM"
edits
n
print .normalized_labels
undo
print .normalized_labels
unwatch normalized
```

Последовательность рассчитана на расширенный `example.vrl`: при остановке
`normalized = "DEV"`, затем `set` меняет значение перед записью в event на строке 44.
`undo` повторно выполняет программу до текущей позиции и возвращает исходный результат.
Секция `LOCALS DIFF` показывает появление, изменение и исчезновение locals текущей
области, включая выход из неё. `show locals off` скрывает также автоматический diff
locals; команда `diff locals` всегда выводит его явно.

`set` принимает JSON-значения, а не выражения VRL. Например:

```text
set .level = "DEBUG"
set .items[0].price = 100
set parsed.user = "bob"
```

Правка применяется в текущей позиции, перед следующей подсвеченной командой.
Предстоящее присваивание может её перезаписать. Из locals разрешено менять только
доступные в текущей области переменные; исторические locals завершённой итерации
не редактируются. Поля event можно создавать. Правка внутри цикла привязана к номеру
итерации и позиции тела: изменённый `normalized` не переносится на другие итерации.

Правки вставляются в генерируемый VRL при replay; исходная программа и входной JSON
на диске не меняются. Добавление или удаление правки пересоздаёт кеши и повторно
доводит выполнение до текущей позиции. `previous`, `goto` и `restart` сохраняют
правки: они снова применятся при достижении своих позиций. Правки шага 0 влияют и на
состояние после `restart`. `undo` удаляет последнюю правку, `edits clear` — все правки.
Наблюдения и breakpoints сохраняются. Все настройки действуют только в текущей сессии.

Перед применением `set` пробный replay должен успешно завершиться и показать
запрошенное значение. Некорректный JSON, недоступные locals, неподдерживаемые Vector
значения или типы и ошибки replay оставляют текущую сессию без изменений. Последующие
команды всё ещё могут отвергнуть изменённый тип при компиляции или выполнении.
Для удаления правки тоже требуется успешный replay до текущей позиции; при ошибке
вернитесь на более ранний шаг и повторите удаление. Replay повторяет прежние побочные
эффекты и может выбрать другой путь в недетерминированной программе; правки в
недостижимых позициях не применяются.

### Вход внутрь if/else

Когда `>` указывает на `if`, выполните `i` (также `into` или `step into`).
Vector вычислит условие, и стрелка перейдёт к первому выражению выбранной ветки,
ещё до его выполнения. Последующие `next` выполняют её выражения по одному.
На вложенном `if` можно снова вызвать `i`; обычный `next` выполнит вложенный блок целиком.
Поддерживаются `else if`, `else`, отсутствие `else`, простые присваивания
`value = if ...` и `.field.path = if ...`. Присваивание результата `if` происходит
только при завершении блока. На прочих выражениях `i` действует как `next`.

Для примера с двумя начальными присваиваниями:

```text
next
next
step into
next
locals
previous
next
continue
```

После последнего выражения ветки отладчик автоматически выходит из блока.
Если ни одна ветка не выбрана, `i` сразу завершает `if`. Условия вычисляет Vector,
Python не пытается угадать выбранную ветку. Номер `Step N/M` по-прежнему считает
завершённые top-level expressions; внутри блока позицию показывают исходные строки
и надпись `Inside if/else`. Diff относится к предыдущему наблюдаемому снимку.

`previous` перемещается по снимкам текущего блока, в том числе сразу после его завершения.
После перехода к следующему top-level expression навигация назад снова работает
по top-level шагам. `goto` и `restart` выходят из внутренней навигации. `continue`
продвигается по текущей ветке до настроенного breakpoint, в том числе перед
отдельной командой внутри ветки.

Каждый внутренний шаг заново запускает исходный префикс с диагностическим `return`
в выбранных точках блока. Условие и предыдущие выражения выполняются повторно;
выражения после достигнутой точки **не выполняются**. Временная программа всё же
компилируется целиком до конца содержащего top-level expression, поэтому ошибка
компиляции далее в этом блоке может помешать войти в него. Диагностика Vector
показывает строки сгенерированного кода (`--show-generated-vrl`), а стрелка — исходные.
Для этой возможности установленный Vector должен поддерживать `return`.
Промежуточные снимки и ошибки также кешируются, отдельно для `next` и `step into`.

### Проход по итерациям for_each

Когда стрелка указывает на `for_each`, команда `i` останавливает отладчик перед
первой итерацией. В `FOR_EACH` видны **номер итерации от 1**, фактический индекс
массива или ключ объекта и значение элемента. Параметры closure с их исходными
именами и доступные внешние locals показаны в `LOCALS`. Индекс массива по-прежнему
начинается **с 0**. Порядок обхода объекта определяет Vector, а не Python.

На заголовке итерации `next` выполняет **одну итерацию целиком** и показывает
следующую. Ещё одна команда `i` входит в **тело текущей итерации**: стрелка
переходит к первому выражению. Каждый `next` выполняет одно выражение тела,
а в `LOCALS` появляются уже присвоенные переменные, например `normalized`.
Повторные присваивания обновляют значения; парные присваивания также поддерживаются.
Команда `i` на выражении тела действует как `next`. Вложенные условия и циклы
внутри тела по-прежнему выполняются целыми выражениями.

После последнего выражения стрелка отмечает закрывающую скобку, а locals остаются
доступными для просмотра. Следующий `next` переходит к первому выражению новой
итерации, очищая локальные переменные предыдущей. Режим тела сохраняется до конца
цикла. `previous` возвращает промежуточные снимки и снимок конца тела. Пустая
коллекция завершается сразу. Команда `next` до входа в цикл по-прежнему выполняет
весь цикл за один шаг.

Закрывающая скобка подписана **End of iteration**, а не пронумерована как ещё одно
выражение тела. В режиме тела `i` и `n` выполняют выделенное выражение одинаково;
их чередование не меняет проход. Вложенные блоки остаются атомарными. Интерфейс
отдельно показывает top-level expression в работе и число завершённых выражений
в заголовке `Step N/M`.

Чтобы увидеть `normalized` в цикле по объекту из примера:

```text
goto 12
i
i
next
locals
```

Первый `i` входит в цикл, второй — в тело. После `next` в LOCALS будет
`normalized = "DEV"` или `"OPS"`, в зависимости от текущего ключа; следующее
присваивание поля ещё не выполнено. Для автоматического показа locals можно
использовать `show locals on`. Чтобы выполнять итерации целиком, используйте
`next` вместо второго `i`.

В цикл внутри открытого `if` можно войти отдельно. `previous` возвращает кешированные
снимки итераций, `continue` идёт до breakpoint или завершения цикла, `goto` / `restart` выходят из внутренней
навигации. Кеш различает итерации и позиции внутри тела. Runtime-ошибка сохраняет
последний успешный снимок, включая locals, вычисленные перед неуспешным выражением.
Breakpoint на поддерживаемой команде тела останавливает перед ней в каждой итерации.

Команда `finish iteration` (`fi`) с заголовка итерации или из любой позиции тела
завершает только текущую итерацию. Следующая показана на заголовке: `n` может
выполнить её целиком, а `i` — снова войти в тело. После последней итерации команда
останавливается сразу за циклом. На закрывающей скобке она просто выходит из уже
завершённой итерации. Сохранённые locals завершённой итерации доступны для просмотра.

Команда `finish loop` (`fl`) завершает все оставшиеся итерации и останавливается
перед следующим выражением. Если цикл находится внутри `if`, команда останавливается
перед следующим выражением этой ветки, не завершая весь `if`. Внутри она проходит
по снимкам итераций, сохраняя навигацию назад и последний успешный снимок при ошибке.
Обе команды завершаются на ошибке, игнорируют breakpoints и требуют активной итерации
`for_each`. В отличие от них, `continue` может выполнить и выражения после цикла.

```text
i
i
next
finish iteration
finish loop
source all
```

При выполнении итерации целиком её прямые локальные переменные тоже сохраняются.
В LOCALS текущей области указан номер активной итерации, а в
`LOCALS · Completed iteration N` — сохранённые locals конца итерации с её ключом/
индексом и значением. Это разные снимки: `normalized = "DEV"` для ключа `"env"`
не является переменной следующей итерации с ключом `"team"`. Locals последней
итерации доступны сразу после завершения цикла; `previous` возвращает предыдущие снимки.
Locals завершённой итерации показаны на заголовке следующей итерации и после цикла.
При проходе внутри тела выводятся только locals текущей итерации; сохранённый снимок
предыдущей не печатается рядом с ними.

Например, `goto 12`, `i`, `next`, `locals` покажет `normalized = "DEV"` первой
завершённой итерации объекта без входа в тело. Для просмотра отдельных присваиваний
используйте второй `i`, описанный выше. Прямые присваивания и параметры closure
собираются в режиме best effort; locals внутри вложенных атомарных блоков не захватываются.

Vector запрещает `return` внутри closure. Поэтому отладчик добавляет служебные
локальные переменные счётчика и снимка, сохраняет диагностику в нужной позиции
итерации и пропускает оставшиеся выражения тела и будущие итерации через условие.
Сохранённый снимок возвращается
**за пределами** closure. Vector ещё может перечислять оставшиеся элементы,
но их исходные тела и последующие пользовательские выражения после точки остановки
не выполняются. Входное выражение и предыдущие итерации повторяются с исходного event.
Как и при обычном replay, весь префикс сначала должен успешно скомпилироваться.

### Проверки на расширенном примере

`example.vrl` работает с существующим `event.json`. Он содержит обход массива
и объекта, вложенные циклы, пустой массив, цикл внутри `if`, нормализацию строк,
изменение массива, вычисления, удаление поля и обработку ошибки JSON.
Для первого цикла выполните:

```text
goto 9
i
next
locals
diff
previous
next
next
next
continue
```

`goto 9` выполняет подготовку перед expression 10 — первым `for_each`. Три итерации
дают промежуточные суммы **20, 27, 42**. Итоговые значения: `.average = 14.0`,
`.names = ["APPLE", "PEAR", "BANANA"]`,
`.normalized_labels = {"env": "DEV", "team": "OPS"}`,
`.pairs = ["A-1", "A-2", "B-1", "B-2"]`, `.discounts = [5, 10]`,
`.parse_status = "handled error"`. Поля `.scratch` и `.unexpected` отсутствуют.

Для намеренной runtime-ошибки добавьте `"debug_fail": true` в **копию** входного
JSON. В последнем `if` находится цикл разбора строк `"1"`, `"2"`, `"bad"`.
Войдите и в `if`, и в цикл: первые две итерации успешны, третья завершается ошибкой
с сохранением `.debug_value = 2`. Стандартный input эту ошибку не вызывает.

## Аргументы

- `--version`: вывести версию отладчика и завершить работу; Vector и входные файлы не нужны.
- `--vector PATH`: бинарник; по умолчанию поиск `vector` в PATH.
- `--program FILE`: VRL-файл, UTF-8.
- `--input FILE`: один JSON object, допускается многострочный JSON.
- `--event-index N`: вместо обычного JSON прочитать N-й непустой JSONL record,
  нумерация с **1**. Выбранный event должен быть object.
- `--timeout SECONDS`: ограничение каждого subprocess, по умолчанию 10 секунд.
- `--no-color`: отключить цвета, сохранив рамки шагов, заголовки и маркеры diff.
- `--no-event`: скрыть EVENT при автоматическом выводе состояния, включая запуск
  и навигацию. Команда `event` / `e` показывает его по запросу; locals и diff остаются.
- `--colors FILE`: файл палитры INI; по умолчанию `vrl-debug.ini` в текущем каталоге.
- `--show-generated-vrl`: выводить сгенерированный VRL перед каждым его запуском,
  включая стартовую проверку и возможный fallback locals.
- `--verbose`: показывать argv как JSON-массив (без неоднозначного shell escaping),
  stderr успешных запусков и traceback внутренних ошибок.

Ошибки JSON, NaN/Infinity и input, отличный от object, отклоняются до запуска Vector.
Входные текстовые файлы могут содержать UTF-8 BOM; создаваемые файлы — UTF-8/LF.

## Оформление и палитра

Каждый результат команды навигации ограничен горизонтальными линиями. Заголовок
показывает номер шага и выполненные строки либо действие (`previous`, `goto`, вход
в ветку). `SOURCE` содержит следующую команду со стрелкой `>`, а `EVENT`, `LOCALS`
и `DIFF` — полученное состояние. Пустые секции занимают одну строку. В diff
добавления отмечены `+`, удаления `-`, изменения `~`; эти маркеры остаются без цвета.

Палитра автоматически загружается из `./vrl-debug.ini` при старте. Если файла нет,
используются встроенные настройки. В файле можно указать только нужные параметры:
остальные сохраняют значения по умолчанию. Это относится и к файлу, явно указанному
через `--colors`. Ошибки формата, неизвестные параметры и цвета выводятся при запуске,
чтобы опечатки в настройках не оставались незамеченными.

В проект включён редактируемый `vrl-debug.ini` с зелёным приглашением и белыми
заголовками. Например:

```ini
# Комментарии начинаются с # или ;
[colors]
prompt = bold green
heading = bold white    # SOURCE, EVENT, LOCALS, DIFF
; Остальные настройки необязательны
next = bold yellow
```

Другой файл можно выбрать так:

```bash
python3 vrl_debug.py --program example.vrl --input event.json --colors my-colors.ini
```

| Параметр | Элемент | Встроенное значение |
| --- | --- | --- |
| `prompt` | Приглашение `vrl-debug>` | `bold green` |
| `step` | Рамки и заголовок шага | `bold cyan` |
| `heading` | SOURCE, EVENT, LOCALS, DIFF, FOR_EACH | `bold default` |
| `next` | Следующее выражение со стрелкой | `bold yellow` |
| `added` | Добавленные значения | `green` |
| `changed` | Изменённые значения | `yellow` |
| `deleted` | Удалённые значения | `red` |
| `error` | Заголовок ошибки и строка с `!` | `bold red` |
| `muted` | Контекст исходника и пояснения | `dim` |

Доступны цвета `default`, `black`, `red`, `green`, `yellow`, `blue`, `magenta`,
`cyan`, `white` и яркие варианты с префиксом `bright_`, например `bright_white`.
Стили `bold`, `dim`, `underline` можно комбинировать через пробел:
`bold underline cyan`. Значение `none` или пустая строка отключает оформление
конкретного элемента. `default` использует цвет текста терминала и подходит
для светлых и тёмных тем. Комментарий после значения отделяется пробелом.

Цвета включаются только при выводе в TTY и автоматически отключаются для файла
или pipe, при `--no-color`, переменной окружения `NO_COLOR` либо `TERM=dumb`.
ANSI-коды из исходной диагностики Vector удаляются независимо от палитры.
Настройки перечитываются при следующем запуске; файл не обязателен для single-file версии.

## Как работает replay

Для шага N создаётся префикс из первых N expressions и запускается отдельный процесс
Vector **с исходным input**. Если передавать результат предыдущего шага, присваивания
применялись бы повторно к изменённому event, а локальные переменные терялись бы.
Replay восстанавливает и event, и окружение locals самим Vector.

Состояния, включая ошибки, кешируются по номеру шага внутри одной сессии.
Программа и исходный input фиксированы на её время, поэтому это эквивалентно ключу
«программа + input + номер шага». `previous` и повторный `goto` используют кеш.
Для нового `goto` промежуточные шаги вычисляются по порядку: diff всегда относится
к непосредственно предыдущему expression. Редактирование файлов во время сессии
не перечитывает их; для нового input, кода или сброса кеша запустите процесс заново.

### Обмен с Vector

На проверенном Vector 0.58.0 CLI предлагает `--program`, `--input`, `--print-object`,
но не отдельный JSON-output флаг. Обычный вывод и `--print-object` отображают VRL values:
например, timestamp записывается как `t'...'`, что не является JSON.
Поэтому отладчик добавляет диагностическое выражение:

```vrl
encode_base64(encode_json({
    "__vrl_debugger": true,
    "event": .,
    "locals": {"parsed": parsed}
}))
```

Vector сам сериализует значения в JSON. Base64 превращает JSON в ASCII-строку,
для которой представление CLI однозначно декодируется JSON-парсером Python.
Человекочитаемые объекты VRL не парсятся. Возможность такого обмена проверяется
при старте; диагностический объект не записывается в пользовательский event.
Перед диагностикой добавляется разделитель, чтобы не дополнить незавершённое присваивание.

Вызовы используют временные файлы `tempfile` с автоматическим удалением,
`subprocess.run` без shell, захват stdout/stderr и timeout. Для временных файлов
можно задать стандартную переменную `TMPDIR`.
Код возврата 0 сам по себе не означает успех: runtime error и `abort` на проверенном
Vector возвращают 0 без результата. Отладчик проверяет наличие и формат envelope.
Ошибки различаются как `syntax`, `compile`, `runtime`, `cli`, `timeout`, `protocol`;
неожиданные Python-ошибки отображаются отдельно как internal debugger error.
Классификация compile/syntax использует диагностические коды Vector; при смене формата
stderr она может стать менее точной, но исходная диагностика сохраняется.

## Ограничения

- Вход поддерживается для распознанных `if/else`, итераций `for_each` и выражений
  тела итерации. Вложенные блоки внутри тела цикла и прочие функции с closures
  выполняются целиком; `step out` пока отсутствует.
  Сложные формы вроде `if` внутри вызова функции, присваивания пути с кавычками
  или объектного литерала на верхнем уровне условия остаются одним выражением.
- Scanner структурный, не полный VRL parser: учитывает вложенность, кавычки,
  escapes, комментарии `#`, `;` и продолжения выражений. Неоднозначные конструкции
  может объединять в более крупный шаг; будущие расширения синтаксиса могут потребовать обновления.
- Locals — best effort: простые `foo = ...` и парные `value, err = ...` на верхнем уровне
  и в открытых через `step into` ветках. Локальные переменные ветки исчезают после
  выхода из её области видимости. Присваивания `.foo`, `foo.bar` не объявляют locals;
  параметры `for_each` собираются перед итерацией, а прямые присваивания тела —
  после выполнения соответствующего выражения в режиме тела и в конце итерации,
  выполненной целиком. Locals завершённой итерации выводятся отдельно. Locals вложенных
  блоков, выполненных целиком, и прочих функций с closures не собираются.
  Если чтение locals не компилируется, запускается префикс без locals и показывается причина.
  Повторный запуск делается только после compile failure, до выполнения VRL.
- Ранний `return` может обойти диагностическое выражение. Тогда шаг сообщает protocol error,
  сохраняя предыдущее состояние. `abort` считается runtime error.
- JSON-снимки не сохраняют отдельные типы VRL timestamp/regex/bytes: их представление
  определяется `encode_json` установленного Vector. Event после преобразования может
  стать массивом или скаляром; diff это поддерживает.
- Replay повторяет внешние эффекты выполняемого префикса. Время, случайность, окружение
  и внешние данные могут давать разные результаты между шагами. Кеш фиксирует первое
  наблюдение шага. Diff недетерминированной программы может включать изменения предыдущих expressions.
  Если при replay выбирается другая ветка, внутренняя точка может быть пропущена:
  отладчик покажет следующую достигнутую точку или завершённый блок.
- `vector vrl` имеет собственный контекст, который не воспроизводит всю конфигурацию
  работающего Vector: enrichment tables, secrets и окружение transform автоматически не загружаются.
- Массивы сравниваются по индексам. Перемещение элемента может дать несколько изменений.
- Новые шаги требуют запуска процесса и повторения префикса; большие программы работают медленнее.

PlantUML нужен только для документации; сам отладчик не требует Java.

Backend не зависит от terminal UI; его можно использовать в другом интерфейсе.
Исходники для разработки остаются в `vrl_debugger/`. После их изменения пересоберите
автономный файл (сборщик также использует только Standard Library):

```bash
python3 tools/build_single_file.py
```

Тесты проверяют соответствие собранного файла исходникам и запуск из отдельного
каталога без пакета `vrl_debugger`, в изолированном режиме Python (`-I`).

```bash
python3 -m unittest discover -v
```

Интеграционные тесты пропускаются, если Vector не найден. Для явного выбора:

```bash
VECTOR_BINARY="$PWD/.tools/vector-x86_64-unknown-linux-gnu/bin/vector" \
  python3.8 -m unittest discover -v
```

Тесты охватывают scanner, diff, исходный input при каждом replay, кеш,
навигацию после ошибки, breakpoints, input JSON/JSONL, timeout, отсутствие бинарника,
несовместимый CLI, locals fallback, настоящий Vector и полный сценарий REPL.
